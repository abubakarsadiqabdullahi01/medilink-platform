# Gap reconciliation: all 410 gaps against `main` at `9a93861`, and what changed after it

*Written 14 October 2026 against System Blueprint v3.0 (code read at `5c199c1`) and Module Reference v3.0.*

The Blueprint’s gap register holds **410 gaps**: 119 P0, 225 P1, 66 P2. Since it was written, 71 commits (the Phase 0 work, pull request 1) landed on `main`. This file says, for every gap, whether the behaviour it describes is **closed**, **partly closed** or **still open** at `9a93861`, and why. It is the reconciliation that the Module Completion Plan asks for as the first step of G0.

## How each mark was made

- **P0 (119 gaps).** From [Phase0-progress.md](Phase0-progress.md), which records for each fix what changed, the commit and how it was shown to work. The counts there (87 fixed, 18 in part, 14 not done) were re-derived from its tables against the Blueprint’s P0 list and agree exactly; every P0 identifier is accounted for and none is listed that is not in the register.
- **P1 and P2 (291 gaps).** Phase 0 aimed at the P0s, so these were not tracked as they went. Each was judged afterwards by reading the current code against the gap’s description and the evidence the Module Reference cites (`file:line` at `5c199c1`), checking what changed in those files since, and searching for the behaviour where the cited files were untouched. Six reviewers each took an area; each mark that moved a gap to closed was checked a second time against the code. The reviewers were told to mark a gap open when they could not show it closed.

| Mark | Meaning |
| --- | --- |
| `CLOSED` | The behaviour described no longer occurs, and a commit or `file:line` shows where it is handled now. |
| `PARTIAL` | Part of it is fixed; the note says what remains. |
| `OPEN` | The behaviour or the missing feature is still there. For a P0 the note says what it needs from outside engineering. |

**What this is not.** A P1 or P2 mark is one reading of the code, not a test; nothing was run for it. A mark with † is `OPEN` because the cited files are unchanged and a search found nothing that implements the behaviour elsewhere: a fix in a place nobody looked would be missed. A gap marked open may therefore be closed by something not found, and the cost of that error is a task that gets re-checked, not a defect shipped. The reverse error is the dangerous one, and the marks `CLOSED` were each checked for it.
